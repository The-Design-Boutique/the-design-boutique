Measuring What Matters

Questions before we set up tracking  |  The Design Boutique  |  July 2026

The new site can measure almost anything. That is exactly the problem: measuring everything produces a dashboard nobody reads, and the useful version of this is short.

So before anything is set up, this asks what actually counts as a good day for the business. Your answers decide what gets tracked, what appears in the editor, and what is deliberately left out. There are no wrong answers here and several of the questions may not have one yet, which is itself useful to know.

Where things stand today

The site records every form submission and keeps it in the editor, so no enquiry is being lost right now. What it does not do is tell you where those people came from, which pages did the persuading, or how many people nearly enquired and did not. That is what this is about.

1. What counts as a win?

Everything else follows from this. The obvious candidates for this site:

  • Somebody submits the contact form
  • Somebody taps the phone number
  • Somebody clicks an email address
  • Somebody signs up to the newsletter
  • Somebody books or registers for a Gold event

Which of those genuinely matter, and are any of them not worth counting?

It is worth being ruthless. A newsletter signup and an enquiry from a law firm are not the same event, and if they are counted together the number stops meaning anything.

2. Are some enquiries worth much more than others?

A branding project and a question about a podcast episode both arrive as a form submission. If one is worth twenty times the other, the site should be able to tell them apart, which usually means asking one extra question on the form.

Is there a rough sense of what a good enquiry is worth, even as a range?

This is not for a report. It decides what is worth optimising: it is only worth improving a page if you know whether the traffic it brings is valuable.

3. Which services do you actually want more of?

The site has ten service pages. They will not all matter equally to the business, and the ones that matter most should be the ones we watch, write about, and improve first.

If you could only grow three of them, which three?

4. What do you want to know each month?

Imagine an email on the first of the month with five lines in it. What are the five lines?

Some options, to react to rather than choose from:

How many enquiries came inThe simplest and probably the most important.
Where they came fromGoogle, direct, social, a referral.
Which pages led to themWhich page somebody read before they enquired.
How the site is doing in searchAlready visible per page in the editor; could be summarised.
What people searched to find youAlso already available, and often the most interesting.

5. Who reads it?

A number that goes to you is a different thing from a number that goes to a client or to the whole team. It changes how it should be worded and how often it should arrive.

Is this for you, for the team, or for reporting outward?

6. Is anything being tracked today?

As far as we can see, the site has no analytics running: no Google Analytics, and no Google Tag Manager container. If something exists that we have not found, knowing about it saves setting up a duplicate and splitting the history in two.

Is there an existing Google Analytics account, or has there been one in the past?

A note on Google Tag Manager, since it will come up

Tag Manager is a container that sits on the site and lets tracking be added or changed without a developer. It is not analytics itself: it is the thing analytics, ad pixels and similar are loaded through.

It is worth having because it means you never have to ask us to add a tracking code again. It is also worth being careful with, because everything loaded through it runs on your site and slows it down, and this site is currently fast. We would set it up, connect analytics through it, and keep the container deliberately sparse.

7. Are there targets already?

A number is much more useful with something to compare it against.

Is there a figure in mind, such as a number of enquiries a month, or a service you want to double? If there is not, that is a perfectly good answer and we can set a baseline from the first few months instead.

What happens with your answers

  1. We set up analytics and a Tag Manager container, connected properly and kept lean.
  2. We mark the things you called wins so they are counted as such rather than as page views.
  3. We surface the few numbers you said you cared about inside the editor, beside the content they describe, so you do not need a separate login to see how a page is doing.
  4. Anything you did not ask for is left out. It can always be added later; a dashboard that gets ignored is very hard to un-ignore.
Nothing here blocks anything

The site works and records every enquiry without any of this. It can be set up before launch or afterwards. The only argument for doing it sooner is that measurement only tells you about the period after you started measuring.

Answer in whatever form is easiest, including a voice note or a reply with rough notes. Partial answers are more useful than none.
